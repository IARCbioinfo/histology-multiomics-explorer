# Tumour Histology and Multi-omics Explorer

**Site:** https://iarcbioinfo.github.io/histology-multiomics-explorer/ · **Issues:** https://github.com/IARCbioinfo/histology-multiomics-explorer/issues

A curated explorer of tumour histology and molecular data. TCGA, a foundational pan-cancer resource, is the reference backbone: the explorer documents curated cohort definitions, RNA-seq and 450k methylation coverage, assay and patient exclusions, histology decisions and sample linkage. Selected published spatial omics studies extend it into tissue and cellular context, usually in different patients. For each resource it records what is available, how modalities are linked, how the data can be obtained and how far each entry has been verified. Archetype analysis is one application and part of the current panel's selection history.

## Agent-ready

The explorer can be used by AI agents and scripts as well as people:

- **MCP server.** `mcp/` is a read-only [Model Context Protocol](https://modelcontextprotocol.io/) server with ten tools: `catalogue_overview`, `get_cancer_type`, `search_resources`, `get_resource`, `search_spatial_sections`, `get_spatial_section`, `get_tcga_cohort`, `search_tcga_patients`, `get_tcga_patient` and `explain_term`. Assistants such as Claude can search resources, tissue sections and TCGA patients, with counts defined as on the site and the release and caveats in every answer.
- **`llms.txt`.** The agent guide: what the site is, the points to read before using any count, and links to every text version ([llms.txt convention](https://llmstxt.org/)).
- **Text and JSON versions.** Markdown versions of the TCGA, spatial and cancer pages (`md/`), one JSON file per cancer page (`data/by-cancer/`), a data index with checksums and JSON Schemas (`data/index.json`, `schemas/`) and a glossary (`data/glossary.json`).
- **`AGENTS.md`.** Instructions for coding agents working on this repository.

The site's [For AI agents](agents.html) page explains each of them.

To use the MCP server, install [uv](https://docs.astral.sh/uv/) and register it; installed this way it reads the published site:

```bash
claude mcp add histology-explorer -- uvx --from "git+https://github.com/IARCbioinfo/histology-multiomics-explorer#subdirectory=mcp" histology-multiomics-explorer-mcp
```

For Claude Desktop, add the same command to `claude_desktop_config.json` under `mcpServers` (see the For AI agents page). From a copy of this repository, `uv run --directory mcp histology-multiomics-explorer-mcp` reads that copy instead; `--source` points the server at another copy or URL. No hosted server is offered.

## Site

The site is static HTML, CSS and JavaScript with no build step and no dependencies. The metadata live in `data/` as JSON, separate from the presentation code in `assets/`. The data file names predate the current name and are kept stable.

## Local preview

Serve the folder over HTTP (opening the files directly does not allow the data to load):

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000/>.

## Checking the data

```bash
python3 scripts/check.py
```

The script checks identifiers, vocabularies, cross-references, required links for matched captures and the rule that core captures are primary tumours with a histology stratum. It also fails if a generated agent file is out of date or a data file does not match its schema. It prints patient and capture counts by stratum and exits with an error if any check fails.

## Agent-readable files

The pages draw their tables with JavaScript, which most AI agents and scripts do not run. The same content is also published as text:

- `llms.txt`: what the site is, the points to read before using any count, and links to everything below ([llms.txt convention](https://llmstxt.org/)).
- `md/`: Markdown versions of the TCGA, spatial and cancer pages, linked from each page's `<link rel="alternate">`.
- `data/by-cancer/<CODE>.json`: one file per cancer page with its TCGA counts, spatial resources, located sections, other resources and evidence.
- `data/index.json`: every data file with its description, record count, size, SHA-256 checksum and schema.
- `schemas/`: JSON Schema (2020-12) for every data file, with types inferred from the data and vocabularies from `scripts/vocab.py`.

`scripts/check.py` also verifies that the MCP server's answers match the data and that every tool is documented here and on `agents.html`. To check the server end to end over the protocol:

```bash
uv run --directory mcp python smoke_test.py
```

Regenerate the agent files after any data change, then run the checks:

```bash
python3 scripts/build_agent_files.py
python3 scripts/check.py
```

Before publication, set `SITE_URL` (links stay relative while it is empty) and `LICENCE` at the top of `scripts/build_agent_files.py`.

## Publishing with GitHub Pages

The repository root can be served directly: in the repository settings, choose **Pages → Deploy from a branch**, branch `main`, folder `/ (root)`. The `.nojekyll` file disables Jekyll processing. All paths are relative, so the site also works under a project subpath.

## Updating the TCGA molecular screen

`scripts/build_tcga.py` documents the GDC queries and PanCanAtlas files it needs. Download them to a folder outside the repository, then run:

```bash
python3 scripts/build_tcga.py /path/to/metadata --date YYYY-MM-DD
python3 scripts/remove_excluded_projects.py
python3 scripts/check.py
```

The rule is applied to screen groups (`GROUPS` in the script): one project each, except CRC (TCGA-COAD + TCGA-READ) and GLIOMA (TCGA-LGG + TCGA-GBM). Projects outside the study (`EXCLUDED`: TCGA-SARC, which combines several sarcoma types, each below the size threshold) stay in the script's outputs for validation and are then removed from the patient-level files by `scripts/remove_excluded_projects.py`; their project-level availability stays in `tcga_counts.json`. The script stops if the 150 / 100 rule no longer selects every listed group, or selects a project that is neither listed nor excluded.

The patient review is imported from its review packet (`tcga_panel_public_review.json`, `tcga_panel_cohort_counts.json`, `histology_and_molecular_strata.json`, `panel_revision_validation.json`), and the import stops if any recomputed count, patient list, stratum or normal-reference figure differs from the packet:

```bash
python3 scripts/import_patient_review.py /path/to/patient-review-packet
python3 scripts/remove_excluded_projects.py
python3 scripts/check.py
```

## Updating the metadata

Edit the JSON files in `data/`, update `data/release.json` with a new version and date, run `scripts/build_agent_files.py` and `scripts/check.py`, and review the diff before publishing. Large images and molecular files stay at their original repositories; the explorer stores links only.

## Citing data

Cite the original publications and repositories listed for each entry. Listing in the explorer does not imply that access has been granted.
